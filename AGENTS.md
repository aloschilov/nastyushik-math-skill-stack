# Repo Instructions For Codex

## Формат математических формул

Все новые математические выражения в заданиях, ответах, обратной связи, Markdown-документах и строках генераторных скриптов нужно задавать в LaTeX-нотации.

- Inline-формулы оформлять как `\( ... \)`.
- Отдельные многострочные формулы оформлять как `\[ ... \]`.
- Не писать формулы в plain text вроде `x^2`, `<=`, `>=`, `->`, `*`, если это не объяснение синтаксиса.
- Использовать `\(x^2\)`, `\(\le\)`, `\(\ge\)`, `\(\Rightarrow\)`, `\(\cdot\)`, `\(50^\circ\)`.
- Десятичные дроби в русской записи писать через запятую внутри LaTeX: `\(1{,}5x\)`, `\(0{,}5x \cdot 8x^2 = 4x^3\)`.
- В пользовательских PDF формулы должны быть отрендерены как математические символы или изображения, а не показаны буквальным текстом `\(...\)`.
- В пользовательских PDF не оборачивать формулы в Markdown backticks. Backticks допустимы только когда обсуждается сам синтаксис LaTeX или имя команды.

Текущий стандарт репозитория: LaTeX-исходник в Markdown/скриптах и отрендеренные формулы в PDF.

## Генерация дневных материалов

- Для новых дневных комплектов сохранять существующую структуру: фидбек ребёнку, фидбек родителю, задания следующего дня, ответы и акценты.
- При создании новых `scripts/generated/make_day*_pdfs.py` все математические строки сразу писать в LaTeX-нотации.
- Если формула попадает в `reportlab` `Paragraph`, рендерить её перед вставкой в PDF. Допустимый текущий способ: превращать фрагменты `\( ... \)` в inline PNG через установленный TeX (`latex` + `dvipng`) и вставлять через `<img>`.
- Нельзя сдавать PDF, где ребёнок видит сырые LaTeX-маркеры `\(`, `\)`, `\le`, `\ge`, `\Rightarrow`, `\circ`, `\cdot`.
- Старые PDF и старые сгенерированные скрипты не переписывать только ради смены нотации.

## Проверки

После изменения repo-level инструкций или prompt-шаблонов запускать:

```bash
python3 scripts/validate_matrix.py
git diff --check
```

Если задача связана с генерацией PDF, дополнительно:

```bash
pdftotext path/to/file.pdf - | rg '\\\\\(|\\\\\)|\\\\le|\\\\ge|\\\\Rightarrow|\\\\circ|\\\\cdot|[A-Za-z]\^[0-9]'
```

Команда не должна находить совпадений в пользовательских материалах. После этого рендерить новые PDF через `pdftoppm` и визуально проверять страницы.
